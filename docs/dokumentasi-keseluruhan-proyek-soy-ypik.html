1. Ringkasan Proyek

SOY YPIK adalah aplikasi operasional internal yayasan yang menggabungkan pengelolaan aset, laporan maintenance, finance, komunikasi internal, user management, announcement, reminder, serta blasting WhatsApp dan email dalam satu codebase Laravel.

Tujuan Sistem
  • Mengurangi proses manual administrasi internal.
  • Menggabungkan data aset, finance, user, dan komunikasi.
  • Menyediakan blast WhatsApp/email dengan log dan retry.
  • Menyediakan kontrol sistem tingkat tinggi melalui Sistem Management.
Karakter Aplikasi
  • Server-rendered menggunakan Blade.
  • Queue dipakai untuk pekerjaan blast dan proses berat.
  • Role-based access control melalui config dan middleware.
  • Gateway WhatsApp berjalan sebagai aplikasi Node.js terpisah.

3. Arsitektur Aplikasi

Alur request Laravel yang paling umum:

  1. Route didefinisikan di routes/web.php.
  2. Middleware memeriksa login, maintenance, fitur aktif, permission, dan audit akses.
  3. Controller menerima request, melakukan validasi, lalu memanggil service.
  4. Service menjalankan business rule dan operasi data.
  5. Model Eloquent membaca/menulis database.
  6. Blade di resources/views merender tampilan.
  7. Job queue menjalankan proses berat seperti blast email/WhatsApp.
Prinsip pengembangan proyek ini adalah menjaga business logic di service, bukan menumpuk semua logika di Blade. Untuk fitur besar, awali dari route, controller, service, model, migration, lalu view.

7. Maintenance Mode

Status maintenance disimpan di app_settings dengan key system.maintenance.

  • Jika aktif, user umum, admin, dan role lain tidak bisa memakai web.
  • Sistem Management tetap bisa login dan membuka console.
  • Pesan maintenance dapat diubah dari halaman Sistem Management.
  • Tujuannya adalah maintenance berkala tanpa kehilangan akses pemulihan.

10. Blasting WhatsApp

Modul WhatsApp blast mengirim pesan ke penerima manual maupun penerima database. Pengiriman diarahkan ke queue agar request web tidak terlalu lama dan mengurangi risiko timeout.

Komponen Penting

FileFungsi
app/Http/Controllers/Admin/BlastController.phpForm, validasi, activity log, retry, gateway device.
app/Services/Blast/WhatsAppBlastService.phpService pengiriman WhatsApp.
app/Providers/Messaging/GatewayWhatsappProvider.phpProvider gateway internal.
app/Jobs/Blast/SendWhatsappBlastJob.phpJob queue kirim WhatsApp.
whatsapp-gateway/srcAplikasi Node.js untuk koneksi WhatsApp dan queue gateway.

Fitur Operasional

  • Kelola perangkat WhatsApp mirip device control.
  • Scan QR, reconnect, disconnect, activate device, rename, dan reset device.
  • Monitoring queue gateway: waiting, active, delayed, failed, completed.
  • Retry tersedia untuk status failed dan pending gateway/antrian gateway.
  • Timeout gateway diperpanjang melalui WHATSAPP_GATEWAY_TIMEOUT.

11. Kontrol Email dan Gmail SMTP

Kontrol Email adalah versi email dari kontrol perangkat. Fitur ini mengelola akun SMTP yang bisa dipilih sebagai pengirim blast email. Gmail menjadi preset utama.

Fitur Kontrol Email

  • Tambah akun Gmail atau SMTP custom.
  • Preset Gmail: smtp.gmail.com, port 587, enkripsi TLS.
  • Test kirim ke alamat tujuan sebelum akun dipakai.
  • Aktifkan/nonaktifkan akun.
  • Pilih akun sebagai pengirim utama.
  • Melihat status kesehatan, pemakaian harian, tes terakhir, kirim terakhir, dan error terakhir.
  • Limit harian opsional agar akun tidak dipakai melewati batas operasional.

Catatan Gmail

Gmail SMTP harus menggunakan Google App Password, bukan password login Gmail biasa. Aktifkan 2-Step Verification di akun Google, buat App Password, lalu isi password tersebut di Kontrol Email.

12. Blasting Email

Blasting email memakai route admin/blast/email. User bisa memilih penerima manual, penerima database, template pesan, attachment global, attachment per penerima, dan akun email pengirim.

  • Jika Kontrol Email aktif dan ada akun active, akun tersebut otomatis dipakai.
  • Fallback MAIL server tetap tersedia dengan opsi Pakai fallback MAIL server.
  • Pengiriman menggunakan SendEmailBlastJob jika mode queue aktif.
  • Log pengiriman tersimpan di blast_logs.
  • Status failed dapat di-retry dari activity log.
QUEUE_CONNECTION=database
BLAST_EMAIL_MODE=queue
BLAST_EMAIL_ACCOUNTS_ENABLED=true
BLAST_EMAIL_GMAIL_HOST=smtp.gmail.com
BLAST_EMAIL_GMAIL_PORT=587
BLAST_EMAIL_GMAIL_ENCRYPTION=tls
BLAST_EMAIL_GMAIL_TIMEOUT=30

19. Deployment dan Worker

Deploy Laravel

git pull --ff-only origin main
composer install --no-dev --optimize-autoloader
npm install
npm run build
php artisan migrate --force
php artisan optimize:clear
php artisan config:cache
php artisan route:cache
php artisan view:cache

Queue Worker Laravel

php artisan queue:work --queue=blast-whatsapp-high,blast-whatsapp-normal,blast-whatsapp-low,blast-email-high,blast-email-normal,blast-email-low,default --tries=3 --timeout=120

WhatsApp Gateway

cd whatsapp-gateway
npm install
npm run start

Jika memakai PM2 di server:

cd whatsapp-gateway
pm2 restart ecosystem.config.cjs --update-env
pm2 save
pm2 logs wa-gateway --lines 200

22. Prioritas Keamanan

  • Jangan push file .env.
  • Jangan simpan password Gmail, token AI, token gateway, dan APP_KEY di dokumen publik.
  • Ganti password awal semua akun setelah deploy.
  • Batasi akses Sistem Management ke personel tepercaya.
  • Aktifkan HTTPS pada domain production.
  • Backup database secara berkala.
  • Cek audit akses jika ada aktivitas mencurigakan.
  • Jangan matikan fitur Sistem Management karena itu jalur pemulihan utama.
API Tester dan AI Executor adalah fitur sensitif. Keduanya hanya boleh digunakan oleh role tepercaya dan harus diawasi dengan audit akses.
